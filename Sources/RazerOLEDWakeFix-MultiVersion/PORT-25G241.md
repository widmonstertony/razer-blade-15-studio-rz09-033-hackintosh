## Safety differences from the original candidate framework

`Legacy25C56Patterns.hpp` preserves all original find/replace arrays and call offsets byte-for-byte. `Patterns25G241.hpp` is independent; no broad wildcards are used. `PatchPlan.hpp` supplies the same descriptors to the kernel and host tests.

Before the first executable-byte write, preflight requires unique patterns, byte-shape checks, non-overlap, available route symbols, original native call targets and rel32 reachability. Nine routed wrappers pass through without OLED-specific work until the final fully-armed flag is set. This does **not** make Lilu's multi-route operation atomic or prove safe recovery from every allocation/write failure; three delay/retry substitutions could remain after a later failure.

25G241 is rejected by default. The explicit `-razer-oled25g241-test` boot argument allows only the known UUID on Darwin 25.6 for owner-authorized research. It is not a qualification flag. Unknown UUIDs/builds, mismatched code and non-matching physical PCI IDs refuse. Matching PCI IDs alone do not prove the Razer board/panel: owners must check the full hardware profile. A single 25G241 IOSleep FF25 import thunk is accepted only when complete no-fault reads verify its exact instruction shape, checked/aligned GOT slot and canonical IOSleep pointer, while preserving rel32 reachability. Unknown instructions, chains, short reads and wrong targets refuse rather than guess. The 25C56 direct-call path is unchanged.

Never load two OLED kexts with the same identifier. Never use this candidate on the working 26.2 system or remove the gate to force a match.

## Reproduce offline checks

From this source directory, with legally obtained CFL executables and shipping KC:

```sh
clang++ -std=c++17 -Wall -Wextra -Werror -fsanitize=address,undefined test_profiles.cpp -o /private/tmp/razer-oled-profiles
/private/tmp/razer-oled-profiles /path/25C56/CFL /path/25G241/CFL
clang++ -std=c++17 -Wall -Wextra -Werror -fsanitize=address,undefined test_patch_plan.cpp -o /private/tmp/razer-oled-patch-plan
/private/tmp/razer-oled-patch-plan /path/25C56/CFL /path/25G241/CFL
python3 -B offline_audit.py RazerOLEDWakeFix.cpp /path/25G241/CFL --profile 25G241
python3 -B offline_audit.py RazerOLEDWakeFix.cpp /path/25C56/CFL --profile 25C56
python3 -B shipping_audit.py /path/25G241/SystemKernelExtensions.kc /path/25G241/CFL
```

Sanitizer tests cover truncation, every exact-pattern byte mutation, missing/duplicate patterns, byte-shape corruption, unknown/malformed UUIDs, cross-profile rejection, original call-target mismatch and positive/negative rel32 limits. These are not sleep tests.
