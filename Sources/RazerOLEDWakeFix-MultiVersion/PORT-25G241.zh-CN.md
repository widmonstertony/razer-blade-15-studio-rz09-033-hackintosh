## 已确认的移植内容

输入的完整 SHA256、十处指令位置及七个字段的对应表见[英文证据表](PORT-25G241.md#port-map)。下列地址都是 KDK 未加载时的地址，不是当前内核地址；运行时仍按精确指令寻找位置。

| 修改项 | 25G241 起点 / 调用点 | 已核对的含义 |
| --- | --- | --- |
| 面板等待 | 0x427A6 | 面板上电状态循环的 25 ms 等待，等长改为 500 ms |
| 第一阶段重复请求退出 | 0x87A3 | 电压请求计数 r13b，4 → 9 |
| 第一阶段失败判断 | 0x8823 | 同一计数器，5 → 10，保留原跳转 |
| 首次 DDI 启用 | 0x83AB / 0x83C7 | WriteRegister32，在 DPCD 0x102 Pattern 1 前 |
| 第一阶段源端电压 | 0x84BC / 0x84DD | 第一阶段 WriteRegister32，不是第二阶段相似位置 |
| 第二阶段源端电压 | 0x8A8D / 0x8AB0 | 第二阶段独立 WriteRegister32 |
| 第一阶段通道设置 | 0x8533 / 0x8552 | WriteAUX(0x103, 4)，参数寄存器已核对 |
| 第一阶段等待 | 0x8586 / 0x85B0 | 是 IOSleep，不是前面的 IODelay；之后 ReadAUX(0x202, 6) |
| 原生链路设置 | 0x81A0 / 0x81D9 | WriteAUX(0x100, 2)，栈上数据构造已核对 |
| 原生 eDP 设置 | 0x8263 / 0x828E | WriteAUX(0x10A, 1)，值来自 ASR 开关 |

十个匹配在 KDK 和发布代码中各出现一次；七个调用目标与十四个必需的函数符号离线检查通过。符号名字一样不代表运行行为已经验证。

## 候选的防误用机制

旧版十组匹配/替换字节及调用偏移独立保留，新版不使用大范围通配。内核候选和宿主测试共用 PatchPlan 描述。

写入第一处指令前，检查匹配唯一性、后续指令形状、区域不重叠、函数符号、原调用目标和 rel32 距离。九个函数钩子在全部完成前只转发原生调用，不做 OLED 专用操作。**这不意味着 Lilu 多钩子安装是原子事务**；后续分配/写入失败时，前三处时序/重试替换仍可能留下，不能声称所有失败都能自动回滚。

25G241 默认拒绝。只有机主明确批准的隔离测试，才使用 `-razer-oled25g241-test`，且仍要求已知 UUID、Darwin 25.6、正确代码及物理硬件。测试开关不是“已经验证成功”的标记；遇到不符合预期的 IOSleep 导入跳板也会拒绝，不能猜测放行。

不允许两个相同 bundle ID 的 OLED kext 同时加载；不能在当前可用 26.2 系统上试，也不能删掉检查强行加载。

构建通过；带 AddressSanitizer / UndefinedBehaviorSanitizer 的测试覆盖截断、每个匹配字节翻转、匹配缺失/重复、指令形状损坏、未知/损坏 UUID、跨版本拒绝、原调用目标错误及 rel32 正负边界。英文页提供完整复现命令。
