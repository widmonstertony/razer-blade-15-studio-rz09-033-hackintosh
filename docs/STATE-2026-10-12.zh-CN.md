# 我的 26.7.1 验证结果：两套状态，不能合并宣称全部成功

[English](STATE-2026-10-12.md)

我使用仓库记录的 RZ09-0330Q / BIOS 1.06 精确硬件。这里记录 macOS 26.7.1 / 25G241，不是旧 26.2 的结果。

## 我成功唤醒的 OLED 配置

2026 年 10 月 12 日（太平洋时间），我在暂停 NVIDIA、启用原 SSDT-DDGPU 断电表、使用 OLED 4.7.2 和原 R4 服务的状态下，完成一次苹果菜单 Normal Sleep/Wake。系统记录了真实 Normal Sleep 和 Wake，R4 记录 `NUDGE_V3_PASS`、`WAKE_RESCUE_PASS`。我看到顶部短暂闪过横条，然后 Apple Watch 解锁电脑，桌面恢复。

4.7.2 修正了已观察到的阶段门控缺口：Darwin 25.6 下，睡眠尚在进行且未出现显式 framebuffer-0 恢复边界时，延后 rawclock 和 DDIA 恢复。它没有修改成功方案的 R4 时序。断电表未启用时，单独换成 4.7.2 **仍然黑屏**；之后的组合成功是实测证据，不等于已证明唯一根因，也不等于实际测量了独显供电轨。

我的验证范围：

- Wi-Fi、扬声器/麦克风、触控板：我之前已在完整冷启动后确认正常。这次发布不修改它们的驱动或根补丁。
- OLED：NVIDIA-off 状态下的一次菜单睡眠成功。26.7.1 多轮、真实合盖和长期稳定性仍待验证。
- 锁屏：这次由 Apple Watch 解锁。尚未在这个 build 上独立验证“锁住 Watch 后必须输入密码”的情况。
- 10-bit：我手动恢复并确认 1680×945 HiDPI / 3360×1890 / 60 Hz 的 `30-Bit Color (ARGB2101010)`。R4 重画曾使它回到 8-bit；自动保持未修复。我选择暂不为此增加程序/服务或修改 R4。
- 耳机、蓝牙、所有应用/API、发热与全部电源状态没有整体验收。我不会把电脑描述为“完美”。

这个独立备份分支是使用 OLED 4.7.2 的**脱敏 NVIDIA-off 公开基线**，发布它不更新 `main`。配置取自恢复 NVIDIA 前已核验的实体备份，个人身份/密码换成公开占位值，并通过 `NVRAM.Add.nullmoth-remove=1` 与配套 Delete 项固定已有探测禁用状态。公开二进制去除了调试信息，非调试段和符号保持一致，但不是成功开机时的原始私有字节；请先在自己的硬件上用 U 盘验收。私有原始 ESP、根补丁事务、身份信息、Windows BCD 和个人日志不上传。GitHub 仓库不是完整系统备份。

## 我恢复的 NVIDIA 配置：自动初始化通过，睡眠失败

我要求恢复 NVIDIA 应用调用。写入前，工具备份了当前实体 ESP、三份内核缓存、原 R4 文件、已有 NVIDIA 自启程序/名单/plist 和 NVRAM，并核验备份及卸载后的实体重新读回。仅修改：

1. EFI 中 `SSDT-DDGPU.aml` Enabled：`true → false`，AML 本身不改。
2. 删除 Apple 启动 GUID 下临时的 `nullmoth-remove=1` 变量。
3. 启用已有 `com.tonytan.nvidia-app-only` 的下次开机启动；本轮**没有** bootstrap 或 kickstart。

OLED 4.7.2、R4、Intel 显示属性、Wi-Fi/音频/HID、安全设置和当前内核缓存均不变。没有安装新驱动或服务、没有调用 GPU、没有自动睡眠或重启。已有服务仍然每次开机最多初始化一次，文件/build/硬件不匹配时拒绝运行。

**这撤销了成功 OLED 唤醒的一项条件，NVIDIA 启用后睡眠再次失败。** 我冷启动后，已有服务成功初始化独显，报告 16 GiB。随后我在 19:44:57 手动睡眠，系统记录 19:46:55 从 Normal Sleep 唤醒；R4 于 19:47:03 开始但未完成，WindowServer 看门狗记录约 40 秒无回应。用精确 25G241 KDK 解析，其 Intel 驱动地址落在 `IGAccelEventMachine::eventTimeout` 与 `IGScheduler5::checkForProgress`。我强制重启了。这证明显示恢复卡住，不等于已证明 NVIDIA 代码是唯一根因；探测标记、DDGPU 电源策略和初始化状态同时变化。以前的小规模 NVIDIA Metal 测试不代表 CUDA、所有软件、完整显存性能或睡眠兼容。

我现在的电脑仍处于 NVIDIA 启用的研究状态；上传这个备份不会改变当前电脑。后续先区分独显初始化后的电源处理与用户态 Metal 开放的影响，不提供自动睡眠循环、固件重试、运行中卸载驱动或屏蔽看门狗。

## 复现和恢复

先读[精确版本配置指南](MAIN-26.7.1.zh-CN.md)和[根补丁/重装要求](REINSTALL.zh-CN.md)，使用自己的身份信息及合法取得的省略依赖。复制 EFI 不会安装根补丁、R4、BetterDisplay 或 NVIDIA。

在已安装 NVIDIA 的电脑上恢复我成功的 NVIDIA-off 状态：暂停 NVIDIA 自启、设置文档记录的 `nullmoth-remove=1` 驱动探测禁用标记、启用原 SSDT-DDGPU，然后手动完整关机再开机。保留无关 EFI/Windows/Ubuntu 文件及精确安全配对。不要直接调用 ACPI 或卸载运行中的驱动。写入前必须制作并验证自己的备份；我私有的单值事务工具固定本机，不是通用公开安装器。

若已经安装可选自启服务，可用 `sudo /bin/launchctl disable system/com.tonytan.nvidia-app-only` 暂停下一次开机启动，不要卸载服务或热卸载显卡。本分支 EFI 在下一次 OpenCore 启动时设置探测禁用变量；写内置 ESP 前先验收自己的私人 U 盘副本。完整冷启动实际应用禁用配置之前，本轮已初始化的独显仍在运行。恢复本备份后每次开机都会禁用 NVIDIA；之后的研究配置必须同时移除 EFI Add/Delete 中该标记和当前变量，并另行核对 DDGPU 与服务状态。

可选 NVIDIA 配置请完整阅读[前置条件、应用模式与恢复指南](NVIDIA-APP-ONLY.zh-CN.md)。我之前暂缓的系统界面限制实验没有安装，也不应从未提交的修改中自行安装。不能一边启用 NVIDIA、一边保留给它断电的表，然后把组合称为已验证。

如果 NVIDIA 影响我自己的私有安装启动，可以使用之前已安装的 OpenCore **空格 → NVIDIA OFF - Recovery → Y → macOS**，再恢复我的 NVIDIA-off 状态。这个公开分支**不分发** `NV-Disable.efi`，也不保留其菜单入口；公开备份使用持久禁用标记。不要假设全新安装自带我私有的恢复工具。内置盘备份和 GitHub 不能保证彻底失去启动入口时仍可恢复。旧 26.2 分支不能降级 26.7.1 或恢复新版根补丁。
